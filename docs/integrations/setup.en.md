# Set up Telegram and WhatsApp from scratch

[Español](setup.es.md) · [Design](channels.en.md) · [Status and checks](../progress/channels-v0.11.md)

Start with Telegram: create a bot and keep this computer running. WhatsApp also needs a Meta test number and a public HTTPS webhook. The C# adapters have local fixture tests; **no live provider account is connected yet**. Account creation, terms and phone verification belong to the owner. The existing web accounts and login setup are unchanged.

## Prepare local configuration

From the repository root, run:

```powershell
./eng/Start-Channels.cmd -PrepareOnly
```

On Windows this uses PowerShell 7.2+ or the bundled runtime on the prepared host. On other systems use `./eng/Start-Channels.ps1` in PowerShell 7. The launcher creates ignored `deploy/channels/.env`, leaves both transports disabled, generates a random webhook verification token, and restricts configuration/storage access to the local user (and SYSTEM on Windows). Fill it in with an editor: literal values, no quotes or trailing comments. Never put credentials in chat, screenshots, links or commits. This file is separate from the web demo's `.env`.

## Telegram

1. Open official [BotFather](https://t.me/BotFather), send `/newbot`, choose a name and an available username ending in `bot`. Keep the returned token local. [Official instructions](https://core.telegram.org/bots/features#creating-a-new-bot).
2. Put it in `CCAI_CHANNEL_TELEGRAM_ACCESS_TOKEN`. Put its numeric prefix before `:` in `CCAI_CHANNEL_TELEGRAM_ENDPOINT_ID`; `getMe` must verify the actual bot matches that ID.
3. Open your bot using BotFather's link and send `/start` in a private chat. It will not answer until the host is enabled.
4. With the host stopped, run `./eng/Start-Channels.cmd -InspectTelegram`. It reads bot identity and private updates, displays only local chat IDs, sends no reply and advances no checkpoint. Put **your own ID** into `CCAI_CHANNEL_TELEGRAM_RECIPIENTS`. Do not blindly authorize every ID returned.
5. Set `CCAI_CHANNEL_TELEGRAM_ENABLED=true`; leave Meta disabled. Run `./eng/Start-Channels.cmd` and keep that window open. Long polling uses outbound HTTPS; no public hosting or router port is needed. [Bot API](https://core.telegram.org/bots/api).
6. Send `/es`, `¿Cuál es la política de cancelación?`, `/en`, and `What is the cancellation policy?`. Expect approved text with a citation. Test `/human` last: it records a simulated queue and pauses the bot persistently for that route. Restarting does not reset human ownership.

The recipient list accepts comma-separated IDs of deliberately selected demo participants. Groups and unlisted senders receive no model response. An existing Telegram webhook blocks polling; the host never deletes it or drops pending updates automatically.

`CCAI_CHANNEL_AI_MODE=simulated` is the explicit initial mode and requires no model weights. On the prepared host, start the existing pinned Qwen/BGE-M3 providers and set `local-llm` to reuse real local inference. A new index is prepared in the separate channel database. No download, cloud fallback or web profile change occurs.

## WhatsApp test resources

[Meta's Developer Hub](https://whatsappbusiness.com/developers/developer-hub/) offers free test resources. Availability and dashboard labels vary by account. This guide does not promise free production messaging.

1. Sign in at [Meta for Developers](https://developers.facebook.com/apps/) and create an app with the WhatsApp use case/product. Complete account terms and verification yourself.
2. In API/testing setup select the **Meta-provided test phone number**. Add and verify your own phone as a test recipient. Use international digits without `+`, spaces or punctuation. Do not migrate a personal number or buy a BSP subscription for this demo.
3. Fill in these local settings:

| Setting | Value from the dashboard |
|---|---|
| `CCAI_CHANNEL_META_ENDPOINT_ID` | Test Phone Number ID, not the displayed phone number or WABA ID |
| `CCAI_CHANNEL_META_ACCESS_TOKEN` | Authorized token for that resource; temporary tokens expire |
| `CCAI_CHANNEL_META_APP_SECRET` | App Secret from basic app settings |
| `CCAI_CHANNEL_META_API_VERSION` | Graph version shown in the API example, in `vNN.0` form |
| `CCAI_CHANNEL_META_RECIPIENTS` | Verified test recipient's international digits |
| `CCAI_CHANNEL_META_VERIFY_TOKEN` | Keep the random value generated by preparation; use it when registering the callback |

4. Review your dashboard to confirm free test resources. Then set `CCAI_CHANNEL_META_TEST_RESOURCES_CONFIRMED=true` and `CCAI_CHANNEL_META_ENABLED=true`. The flag records the owner's review; it is not an automatic billing-account check. The sender has no templates/campaigns or paid fallback.
5. Start `./eng/Start-Channels.cmd`. Install `cloudflared` from [official downloads](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/), then open a second window:

```powershell
cloudflared tunnel --url http://127.0.0.1:7454
```

6. Register `https://YOUR-TUNNEL-HOST/webhooks/whatsapp` in Meta with your local verification token. Subscribe to `messages` and associate the app with the test WABA as directed by your dashboard. GET verification returns the exact challenge; POST authentication uses the separate App Secret HMAC. [Meta webhook reference](https://whatsapp.github.io/WhatsApp-Nodejs-SDK/api-reference/webhooks/start/).
7. Message the Meta test number from your authorized phone; follow the panel's contact-initiation procedure if required. Try the ES/EN questions. Replies stop after the eligible 24-hour customer window; the host does not create a template fallback. The temporary hostname changes when the tunnel restarts, so update Meta's callback. [Quick Tunnel limitations](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

Tunnel **only port 7454**. Web 7452, source 7453, identity 8080 and model ports remain local. Provider version/token/recipient setup and real callback correlation still need live acceptance; fake HTTP is not proof of Meta compatibility for a selected Graph version.

## Operation and limits

Stop the host and tunnel with `Ctrl+C`. With the host stopped, `./eng/Start-Channels.cmd -Status` prints aggregate inbox/outbox/ownership counts. One process owns the ledger lock, including inspection/status commands. `Sent` records a valid provider response ID, not proof the participant read it. `Unknown` is not automatically resent. Only definitive 429 responses get a bounded retry.

Hourly/startup cleanup logically removes seven-day-old texts/routes and retains deduplication tombstones for thirty days. SQLite is not encrypted by this mechanism; WAL files/backups do not promise secure physical erasure. Do not reset the old web databases to fix a channel.

If configuration is rejected, check IDs, allowlists and token validity locally. If Telegram readiness fails, check for a webhook conflict without automatically deleting it. No private IDs in inspection means send a private text to your own bot first. Meta configuration errors mean the required test resources/version/secrets are incomplete. Model preparation failures require starting pinned providers or explicitly choosing `simulated`. A bot paused after `/human` is expected; authenticated reset is a later slice.

Live completion requires incoming/reply pairs in ES and EN per channel, restart behavior, expired-token handling, simulated handoff and a cost/setup review. Automated checks use isolated data and never send to real recipients.
